# AHL/BKZ block 선택 정책 실험

## 1. 배경

크로스오버 실험에서 AHL/BKZ의 기본 `block=40`이 60×150/80×200에서 단일 시도조차 90초를
넘겨 계산적으로 붕괴함을 발견했다(block을 10/8로 줄이면 1초대로 해결). 이를 계기로
"GNN/RL을 전체 배정 탐색이 아니라 인스턴스별 AHL/BKZ `block` 크기를 고르는 저차원
정책으로 재배치하면 어떨까"라는 방향을 제안했고, 이번 실험으로 검증했다.

## 2. 방법

1. **캘리브레이션**: 5개 크기(10×25~80×200)에서 block=[6..40] 단일 시도 시간을 측정해
   크기별 "안전(빠른) block 후보군"을 정함.
2. **Sweep**: 각 크기의 feasible 인스턴스 풀(10×25/20×50 n=100, 40×100 n=31,
   60×150/80×200 n=30/20)에 대해 안전 block 후보군 전체를 시도하고 성공 여부·시간을 기록.
   60×150/80×200은 초기 tries=3에서 전무했던 성공 신호를 tries=20으로 올려 재확인(부스트 sweep).
3. **특징**: `m, n, m/n, density, vertex_spread, b_tightness`(모두 `difficulty_index.py` 재사용,
   무료/저비용 구조적 특징).
4. **정책 모델**: 2-hidden-layer MLP(64유닛) — 특징 → block 후보별 성공확률(멀티라벨 sigmoid).
   Masked BCE로 학습(크기별로 실제로 시도한 block만 loss에 반영).
5. **평가**: 크기별 5-fold 랜덤 분할(train 75%/val 25%)을 5개 시드로 반복, held-out
   인스턴스에서 정책이 고른 block vs 두 baseline(① 현재 파이프라인 기본값=40,
   ② train split에서 가장 잘 통했던 단일 고정 block)의 성공률을 sweep 데이터에서
   그대로 조회(재실행 없이 오프라인 평가).

## 3. 결과

### 20×50 (유일하게 통계적으로 유의미한 신호가 있는 크기, n=25 val × 5 seed = 125회)

| 방법 | 평균 해결율 | 표준편차 |
|---|---|---|
| 현재 기본값 (block=40) | 36.0% | ±5.7pp |
| 최적 단일 고정 block (block=8 또는 10) | 50.4% | ±4.6pp |
| **학습된 인스턴스별 정책** | **53.6%** | ±9.2pp |

### 다른 크기

| 크기 | 결과 |
|---|---|
| 10×25 | 모든 block에서 100% 해결 — 튜닝 자체가 무의미(퇴화 케이스) |
| 40×100 | 어떤 block도 31개 중 2~3개만 해결 — 신호는 있으나 표본 대비 너무 희박해 정책 학습 불가 |
| 60×150 | tries=3→20으로 올려도 30개 중 1개만 해결(block=10) — 사실상 0에 가까운 천장 |
| 80×200 | tries=20까지도 20개 전부 실패 — block 선택으로 구제 불가 |

## 4. 해석

1. **가장 큰 승리는 "학습"이 아니라 "기본값 교체"다.** 현재 파이프라인의 `ahl_block=40`
   기본값은 20×50에서 측정 가능한 최악의 선택(36.0%)이었다. block을 8~10으로만 바꿔도
   해결율이 +14.4pp 오른다 — 코드 한 줄 수정으로 얻는 이득이 가장 크다.
2. **학습된 인스턴스별 정책은 최적 고정값보다 근소하게 낫지만(53.6% vs 50.4%), 표준편차
   (±9.2pp)가 그 차이(3.2pp)보다 커서 이번 표본 크기로는 통계적으로 확정할 수 없다.**
   즉 "인스턴스 맥락을 보고 판단하는" 추가 복잡도가 주는 이득은 있어 보이지만 미미하고
   불확실하다 — 이 세션 전체에서 반복된 "단순 baseline이 학습된 컴포넌트를 거의 항상
   따라잡는다"는 패턴과 일치한다.
3. **60×150/80×200은 block 튜닝으로 구제되는 문제가 아니다.** tries를 3→20으로
   6배 늘려도 성공률이 사실상 0%에 머물러, 크로스오버 실험에서 확인한 "이 규모에서
   AHL/BKZ 자체가 실용 범위를 벗어난다"는 결론을 독립적으로 재확인한다.

## 5. 권고

- **즉시 반영 가능**: 파이프라인의 `ahl_block` 기본값을 크기별로 교체
  (10×25→6, 20×50→8, 40×100→6, 60×150→10, 80×200→6 — sweep에서 나온 최적 고정값).
  코드 변경 최소, 검증된 이득(20×50 기준 +14.4pp).
- **정책 모델은 당장 배포할 근거가 약함**: 이득이 노이즈 범위 안에 있어, 표본을 늘리거나
  (특히 40×100처럼 신호가 희박한 구간) 더 정교한 특징/모델로 재검증하기 전에는
  "단일 고정값 교체"만으로 충분하다.
