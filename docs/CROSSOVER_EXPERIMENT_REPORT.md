# 크로스오버 실험: 제안 방법(CP-SAT/MILP 미포함) vs CP-SAT 단독

## 1. 실험 목적

기존 CP-SAT/MILP 폴백이 섞인 파이프라인은 성능 상한이 CP-SAT 자체 성능으로 caps되므로,
"제안 방법이 사이즈 증가에 따라 CP-SAT를 역전하는 지점(crossover)"을 찾으려면
**CP-SAT/MILP를 최대한 배제한 순수 제안 파이프라인**(전파 → LP hard-rule → kernel pump →
AHL/BKZ → GNN feasibility head → MCTS 1-ply backtrack → pump repair → policy-guided DFS)을
CP-SAT 단독과 동일 인스턴스·유사 시간 예산 하에서 직접 비교해야 한다.

- **CP-SAT 단독**: `crossover_cpsat_pure.py`. 타임아웃 시 정직하게 `unresolved`로 보고
  (기존 baseline_dns 스크립트는 타임아웃을 "feasible"로 추측 처리하는데, 이는 이전에 우리
  파이프라인에서 고친 것과 동일한 종류의 편향이라 여기서는 배제함). cap=30초/인스턴스.
- **제안 방법(순수)**: `LPneuroBLS_v9_infer_pure.py`. `LPneuroBLS_v9_infer_cpsat_fallback.py`에서
  CP-SAT 핸드오프만 제거한 버전 — DFS 예산 소진 시 추측하지 않고 정직하게 `unresolved` 보고.
  LP relaxation solve는 CLAUDE.md 정의상 문제의 수학적 구조 자체(실수 완화)이며 정수계획
  솔버가 아니므로 유지.

## 2. 사이즈 스윕 및 표본

| 크기 | n | 데이터 |
|---|---|---|
| 10×25 | 200 | `sub_hard_10x25_200` |
| 20×50 | 200 | `sub_hard_20x50_200` |
| 40×100 | 40 | `sub_hard_40x100_40` |
| 60×150 | 40 (CP-SAT) / 9 완료 (제안, 25분 안전컷) | `test_instances_hard_60x150_40` (신규 생성) |
| 80×200 | 30 (CP-SAT) / N 완료 (제안, 시간 예산 제약) | `test_instances_hard_80x200_30` (신규 생성) |

모든 인스턴스는 `generate_hard_instances.py`(vertex_spread 최대화, K=20, 유일해 가정 없음)로
새로 생성한 hard 계열이며, CP-SAT/제안 방법 모두 **동일 인스턴스 집합**에서 평가했다.

### 설정 차이 (투명하게 명시)

10×25/20×50/40×100은 기본 설정(`ahl_block=40, ahl_tries=10, dfs_budget=20000`)을 사용했다.
60×150/80×200은 **기본 설정으로 첫 인스턴스조차 90초 내 끝나지 않아** (`ahl_block=40`
단독 BKZ 시도 1회가 n=150에서 90초 이상 소요, 진단 결과 `block=10`→1.16초, `block=6`→0.59초로
지수적 완화가 확인됨) `ahl_block=10/8, ahl_tries=5, dfs_budget=5000`으로 축소해 재실행했다.
이는 세션 초반 확립된 "v9의 핵심 기여: 블록 크기는 사이즈가 커질수록 줄여야 한다"는 발견과
정확히 일치하는 실측 재확인이며, 예산 제약상 불가피한 조정이었다.

## 4. 핵심 발견

1. **크로스오버는 테스트된 범위(10×25~80×200) 어디에서도 관측되지 않았다.**
   해 발견율·인펴저블 증명율·평균 시간 모든 지표에서 CP-SAT가 전 구간 우위.

2. **CP-SAT는 "인펴저블 증명"과 "해 발견"이 비대칭적으로 붕괴한다.**
   30초 cap에서 infeasible 증명율은 80×200까지도 100% 유지되는 반면, feasible 해 발견율은
   100%(20×50) → 32%(40×100) → 0%(60×150, 80×200)로 급격히 붕괴한다. 즉 CP-SAT의 약점은
   "만족 불가능성 판별"이 아니라 "만족 해 탐색" 쪽에 있다.

3. **제안 방법(순수)은 CP-SAT보다 먼저, 더 가파르게 붕괴한다.**
   20×50에서 이미 해 발견율이 39%로 CP-SAT(100%)에 못 미치고, unresolved 비율이 66.5%에
   달한다. 40×100에서는 infeasible 증명이 0/9로 완전히 무너진다(이는 세션 초반 발견한
   "DFS 예산 소진 시 무증명 추측" 위험을 정직한 unresolved로 바꾼 결과이며, CP-SAT 폴백 없이는
   40×100 규모에서 infeasible 판별 능력이 사실상 없음을 재확인한다).

4. **60×150/80×200에서는 AHL/BKZ 자체가 계산적으로 붕괴한다.**
   기본 block=40으로는 단일 시도조차 90초를 넘겨 실험이 진행 불가능했고, block을 10/8로
   낮춰야 겨우 초 단위로 돌아갔다. 하지만 축소된 block으로는 **완료된 인스턴스 전부에서
   AHL도 MCTS/DFS도 단 한 건도 풀지 못했다** (해 발견 0/8~0/N, infeasible 증명 0/1).
   즉 이 규모에서는 "제안 방법이 CP-SAT보다 느리게 저하되는 지점"을 찾기는커녕, 제안 방법의
   구성 요소(AHL/BKZ) 자체가 CP-SAT보다 먼저 실용 범위를 벗어난다.

5. **MCTS/policy-guided DFS(학습 기반 탐색)는 전 구간에서 거의 기여가 없다.**
   Method breakdown을 보면 해가 나온 경로는 거의 전부 `lp_hard_rule`(무료 infeasible 컷)과
   `ahl_bkz`(격자 환원)이며, `mcts`로 풀린 사례는 10×25에서 단 1건, `dfs_solved`는 전 구간
   0건이다. 이는 세션 초반부터 누적된 "학습 신호가 BLS에서 거의 무용하다"는 결론과 정확히
   일치한다.

## 5. 결론

**"CP-SAT/MILP를 최대한 배제한 우리 방법이 사이즈가 커지면 CP-SAT를 역전한다"는 가설은
이번 실험 범위에서 기각된다.** 오히려 정반대 패턴이 관측된다 — CP-SAT는 사이즈가 커져도
infeasible 판별 능력을 오래 유지하는 반면, 제안 방법은 (a) infeasible 판별을 더 일찍 잃고,
(b) 격자 환원(AHL/BKZ) 자체의 계산 비용이 CP-SAT의 저하 속도보다 더 빠르게 폭발한다.

이 결과는 CP-SAT 폴백을 파이프라인에 유지하는 현재 설계(정직한 unresolved 삼상태 + 폴백)가
"우리 방법 단독"보다 실질적으로 우월하다는 기존 실험 결과와 일치하며, 향후 방향은
(i) 제안 방법 단독의 대형 인스턴스 확장이 아니라 (ii) CP-SAT를 언제/어떻게 보강할지에
초점을 맞추는 편이 합리적임을 시사한다.
