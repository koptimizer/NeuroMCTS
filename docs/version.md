## v5 (2026-07-07)

- **핵심 변경**: LP-guided MCTS + null-space projection(kernel pump) + policy-guided complete backtracking을 결합한 neuro-symbolic 파이프라인 최초 확립.
- **실험**: 10×25 DNS 계열 1,000개(800 feasible/200 infeasible) held-out 테스트.
- **인사이트**: feasibility 분류 정확도 99.50%(FN 0), feasible 해 복원 99.62% — 모든 비정확(inexact) baseline(LP rounding, LLL, BKZ) 대비 4.7~45.5%p 우위. 단, 이 크기에서는 Gurobi/SCIP/CP-SAT 등 정확 solver가 여전히 완벽하고 더 빠름. 61.1%는 신경망 추론 전에 순수 기호적 규칙+pump로 종결.
- **문서**: `docs/tex/LPneuroBLS_v5_report.tex`, `docs/pptx/LPneuroBLS_v5_deck.pptx`

## v6 (2026-07-10)

- **핵심 변경**: 기존 DNS 계열이 "너무 쉬운" 분포임을 확인 → market-split 스타일 hard 계열 신규 구축(10×25/20×50/40×100). 크기 무관 학습(segment softmax), pump-trajectory/marginal 통계 기반 feasibility head, dense terminal reward + reverse curriculum, policy-guided DFS 추가.
- **실험**: hard 계열에서 baseline 재측정, self-play 강화학습 실험, 예산-정확도 스케일링 실험.
- **인사이트**: hard 계열에서 baseline 붕괴 확인(LP rounding 2~27%, LLL/BKZ 최대 99% 오분류), exact solver 시간도 800~7,300배 증가. **self-play가 오히려 성능을 떨어뜨림**(20×50 9.6%→5.9%, 학습 부정 결과 1호). 탐색 예산을 3.8배 늘려도 +4%p뿐 — 병목이 모델/예산이 아니라 탐색 기술(conflict learning, lattice enumeration) 자체임을 특정.
- **문서**: `docs/tex/LPneuroBLS_v6_report.tex`

## v7 (2026-07-10~11)

- **핵심 변경**: self-play 대신 propagation-impact 전문가 모방 학습으로 전환, 크기 이산균등분포($m\sim U\{6,...,20\}$)로 학습, GNN 메시지패싱 반복 횟수를 추론 시점에 분리·조절 가능하게 변경. `LPneuroBLS_v7.py`가 이후 v8/v9의 공유 모듈이 됨.
- **실험**: 엄격한 zero-shot 프로토콜(학습 시 $m>20$ 미노출, 40×100은 순수 외삽 평가), 반복 스케일링(8→32) 실험.
- **인사이트**: 10×25에서 비정확 방법 최초로 100%/100% 포화. 그러나 **모방 학습도 20×50 탐색 성능을 저하시킴**(8.5%→5.5%, 학습 부정 결과 2호, self-play와 독립적으로 재확인) — fail-first(증명)와 succeed-first(탐색)를 하나의 정책이 겸할 수 없다는 CP 고전 원리를 실측. 반복 스케일링은 40×100에서 효과 없음(2.25% 고정).
- **문서**: `docs/tex/LPneuroBLS_v7_report.tex`

## v8 (2026-07-15)

- **핵심 변경**: **AHL(Aardal-Hurkens-Lenstra) 격자 임베딩 + BKZ 축소를 파이프라인 단계로 추가.** conflict-directed backjumping, 커널 격자 열거와 3자 비교 후 AHL만 채택.
- **실험**: CBJ(500K 노드, 300개 소형 전수검증), 커널 열거(LLL+HNF+증명가능 박스), AHL embedding을 20×50/40×100에서 비교.
- **인사이트**: CBJ는 밀도 0.5 조밀 행렬에서 완전히 무효(일반 DFS와 동일, 충돌 이유가 결정 전체를 포함해 백점프 퇴화). 커널 열거는 40개 중 2개만 해결. **AHL은 20×50 단독 51.0%, 파이프라인 통합 후 20×50 9.6%→53.5%, 40×100 2.25%→23.5%** — 이 프로젝트 최대의 단일 성능 도약. 10×25는 1.52s→0.23s로 가속.
- **문서**: `docs/tex/LPneuroBLS_v8_report.tex`

## v9 (2026-07-20)

- **핵심 변경**: AHL의 BKZ block 크기가 인스턴스 크기에 의존하는 최적값을 가짐을 발견하고 튜닝(`--ahl_block`/`--ahl_tries` 인자 정식화). **현재까지 프로덕션 파이프라인의 최종 코드 버전.**
- **실험**: 3,300개 라벨링된 solve trace로 block/tries 스윕, 학습 기반 try-scheduler 시도.
- **인사이트**: block=10이 20×50 최적(75.7%), block=20이 40×100 최적(48.3%) — block=40(v8 기본값)은 40×100에서 시도당 207초로 치명적으로 느림(block=20 대비 85배). 최종 성능 **20×50 78.25%@3.78s, 40×100 66.67%@22.0s**(block=40 대비 13배 가속, 동급 정확도). 학습 기반 스케줄러는 AUC 0.54-0.58로 신호 약함 → 기각(학습 부정 결과 5호).
- **문서**: `docs/tex/LPneuroBLS_v9_report.tex`

## v10 (~2026-07, v9 코드 기반 분석 사이클)

- **핵심 질문**: 학습 컴포넌트(GNN+MCTS+DFS 순서)가 기호적 단계 대비 정확히 얼마나 기여하는가?
- **실험**: 인스턴스 단위 단계별 귀속(waterfall) 분석, 신규 특징 기반 infeasibility 분류기, 60×150 최초 평가.
- **인사이트**: 학습 기여도가 10×25에서 7.6~7.75%p(그나마 유의미)이던 것이 20×50에서 0.4%p, **40×100/60×150에서는 정확히 0**으로 단조 감소. infeasibility 분류기는 AUC 0.588(학습 부정 결과 6호, 그러나 가장 엄밀하게 검증됨 — 정밀도 최고점에서도 flag된 것의 1/3~1/2이 실제로는 feasible이라 무용). **60×150에서 스케일링 절벽 발견**: 40×100의 66.67%에서 60×150의 6.67%로 붕괴, 시간은 22.0s→108.0s.
- **문서**: `docs/tex/LPneuroBLS_v10_report.tex`

## v11 (2026-07, v9 코드 기반 분석 사이클)

- **핵심 질문**: feasibility 분류 자체를 신경망으로 직접 노리면 되는가? 그리고 CP-SAT 등 baseline과 실제로 얼마나 차이나는가?
- **실험**: 분류기 변형 10종(NeuroSAT류 매칭쌍, dual-node GNN, 랜덤 노드 특징, pooling 변형, GS profile 시퀀스모델), baseline 전면 재점검(Gurobi/SCIP/CP-SAT, 60×150 포함 최초), CP-SAT hint/파라미터 실험.
- **인사이트**: 10종 중 8종이 AUC 0.4997~0.5003(순수 우연), 나머지 2종도 0.588/0.599로 실용 불가 — 원인을 표현 자체의 정보 부재로 기계적으로 규명(near-miss 쌍의 96.8%가 GS profile 완전 동일). 문헌(Chen et al. 2023, G4SATBench)이 독립적으로 같은 패턴을 이미 보고했음을 확인. **Baseline 재점검**: classical solver가 40×100까지 전 구간에서 압도(2~200배 빠름), CP-SAT조차 60×150 feasible 12개 중 2개만 30초 내 해결(그래도 제안 파이프라인의 6.67%보다 우위). **CP-SAT에 kernel pump 결과를 hint로 주입**해 infeasibility 증명 5/6→6/6 — 이 사이클 유일한 긍정 결과. 파라미터 3종 재구성은 전부 무효.
- **문서**: `docs/tex/LPneuroBLS_v11_report.tex`, `docs/tex/LPneuroBLS_v11_report_KR.pdf`, `docs/pptx/LPneuroBLS_v11_deck.pptx`

## v12 (2026-08 ~ 2026-09, 본 세션)

별도 리포트(tex)는 아직 작성되지 않음 — 아래는 세션 중 생성된 `docs/*.md` 리포트와 메모리 기록 기반 정리.

### 1. Hard 인스턴스 계열 확립 및 유일해 가정 폐기
- CLAUDE.md 문제 정의에서 "$\mathbf{x}^*$ 유일성 가정"을 명시적으로 폐기(유일성 검증 시 오히려 쉬운 인스턴스로 편향됨을 확인).
- `vertex_spread`(LP 완화 폴리토프 크기) 직접 최대화 방식으로 hard 계열 재구축(`generate_hard_instances.py`, K=20 best-of-K 선택). 25~75% band 강제 방식은 no-op으로 확인되어 폐기.
- 5단계 난이도 지표(`difficulty_index.py`) 정의.
- 문서: `instances/HARD_INSTANCES_README.md`

### 2. 크로스오버 실험 — CP-SAT/MILP 미포함 순수 v9 vs CP-SAT
- 10×25~80×200에서 순수 v9(CP-SAT 폴백 없음)와 CP-SAT 단독을 정직한 tri-state(unresolved 삼상태) 기준으로 비교.
- **결론: 크로스오버 미발견.** CP-SAT가 전 구간 우위. 60×150+부터는 AHL/BKZ 자체가 계산적으로 붕괴(기본 block=40이 90초 이상 소요), block을 줄여도 해결 0%.
- 문서: `docs/CROSSOVER_EXPERIMENT_REPORT.md`

### 3. AHL block / CP-SAT 파라미터 인스턴스별 선택 정책 실험
- 같은 sweep+MLP 방법론을 두 하이퍼파라미터에 적용, 대조적 결과:
  - **AHL block**: 기본값(40) 교체만으로 20×50 +14.4%p(학습된 정책의 추가 이득은 노이즈 수준).
  - **CP-SAT 파라미터**: 오라클(6개 config 중 인스턴스별 최적)이 default와 사실상 동일 → 학습할 신호 자체가 없음(학습 부정 결과 계속).
- 병렬 스윕 시 CPU 경합이 타이밍을 오염시키는 방법론적 함정 발견·기록(jobs=16→jobs=4로 해결).
- 문서: `docs/AHL_BLOCK_POLICY_REPORT.md`, `docs/CPSAT_PARAM_POLICY_REPORT.md`

### 4. 순수 CP(classic OR-Tools) / MILP(Gurobi) 대조 실험
- CDCL 없는 순수 CP는 20×50부터 완전 붕괴(0%, CP-SAT는 100%) — CDCL이 핵심 요인임을 실측 확인.
- Gurobi(MILP)와 CP-SAT를 동일 조건에서 비교 → **거의 완전히 동일한 성능**(60×150/80×200에서는 풀고 못 푸는 인스턴스 집합까지 일치) — 이 문제에서는 솔버 기술보다 인스턴스 구조(폴리토프 크기)가 난이도를 지배함을 시사.

### 5. 5지표 벤치마크 표준화
- **Feasible MCC**(불균형 데이터에서 precision의 base-rate 왜곡 문제를 피하기 위해 채택 — 무정보 시 정확히 0), **Solution ACC**, **Unresolved Rate**, **Avg/STD Cal-time**을 표준 보고 형식으로 확정(사용자 피드백 반영).
- LLL/BKZ/CP-SAT/SCIP MILP를 24:6(feasible:infeasible) 표본, 900초 cap 기준으로 재측정.
- **주요 결과(40×100 기준)**: SCIP 100%, CP-SAT 87.5%, 순수 v9 41.7%. **60×150은 전 baseline·제안 방법 공통 0%**(900초를 줘도 CP-SAT/SCIP/v9 전부 unresolved).
- Gurobi는 세션 중 라이선스 만료 이슈 발생 → 사용자 갱신 후 재개 예정.

### 6. 다중사이즈 파인튜닝 실험 (밤새 학습, 109에포크)
- 10×25/20×50/40×100/60×150 hard train pool(60×150은 세션 중 신규 생성, 1,500개)에서 무작위 크기 샘플링으로 `checkpoint_pretrained.pt`를 109에포크 파인튜닝(`train_hard_multisize.py`).
- **결론: 전 크기에서 Solution ACC 변화 0.** 단계별 기여도 분석 결과 GNN(확률판단)·MCTS가 4개 크기 전 구간에서 기여 0%(v10의 결론을 다시 재확인) — 실제로 푸는 건 AHL/BKZ·전처리·kernel pump뿐이라, GNN을 아무리 파인튜닝해도 결과가 바뀌지 않음. 40×100은 오히려 평균 시간만 3.5배 느려짐(169s→603s).
- 체크포인트: `runs/260819-2251_LP_Hybrid_v7/checkpoint_hard_multisize_final.pt` (git에는 미포함 — 성능 개선이 없어 `best.pth`로 승격하지 않음)

## v13 (2026-09-04 ~ 2026-09-07): AHL 열 순열 RL 정책

**동기**: 지금까지의 학습 실패는 전부 (a) AHL이 이미 잘 하는 일을 신경망이 대신하려 했거나
(b) 표현 자체에 정보가 없는 일(feasibility 분류)을 시킨 경우였음. 이번엔 **AHL이 지금 무작위로
하고 있는 결정** — 매 시도의 열 순열(`rng.permutation(n)`) — 을 RL로 학습 대상 삼음.

### 폐기한 것 (기여율 0% 실측 확인)
v12의 단계별 귀속 분석에서 4개 크기 전 구간 기여 0%로 확인된 단계를 파이프라인에서 제거:
GNN feasibility head의 판단, MCTS 탐색, policy-guided DFS의 *해 탐색* 역할.
남긴 것: 제약 전파, LP hard rule, kernel pump, AHL/BKZ, DFS(infeasibility 증명 전용).
→ `proposed_src/v13_pipeline.py`

### 사전 검증 (RL 붙이기 전 필수 확인) — **통과**
`v13_perm_signal_probe.py`: 같은 인스턴스에 서로 다른 무작위 순열 30개를 시도해 성공률 분포 측정.
- 20×50(block=10): feasible 10개 중 **8개가 순열 의존적**(성공률 3~40%), "항상 성공" 0개
- 40×100(block=20): 10개 중 7개 순열 의존적, 단 성공률 2.7%로 매우 낮음
→ 순열이 실제로 결과를 가른다는 전제가 실측으로 확인됨(학습 여지 존재).

### 방법
- **정책**: 변수/제약 이분 GNN → 변수별 점수 1개. 점수로 Plackett-Luce 분포를 만들고
  Gumbel top-k로 순열 샘플링. 확률 합=1.0 수학적 검증 완료.
- **학습**: REINFORCE + leave-one-out baseline(인스턴스당 8 rollout), 엔트로피 정규화.
  보상 = 그 순열로 AHL 1회 시도해서 검증된 해가 나왔는가(1/0).
- **대조**: 매 스텝 동일 인스턴스에 무작위 순열 8회도 같이 시도해 policy vs random을 실시간 기록.
- **학습 규모**: 10×25/20×50/40×100 혼합, 6시간, **13,390 스텝**.
- → `proposed_src/v13_train_perm.py`, `v13_bench.py`

## v14 (2026-09-07): 변수 고정을 통한 차원 축소 + RL

**동기**: v13까지의 학습 실패는 전부 "인스턴스를 한 번 보고 뭔가를 예측"하는 형태였음.
이번엔 이 프로젝트에서 가장 확실한 사실 — **n이 난이도를 지배한다**(10×25 100% / 20×50 83% /
40×100 54%) — 을 직접 공략: RL이 문제를 푸는 게 아니라 변수를 고정해 **문제를 줄인다**.

### 사전 검증 결과 (`v14_fixing_probe.py`)

**Q1 "차라리 빠른 알고리즘이 고정하고 RL이 나머지를 풀면?"** → 그럴 재료가 없음:
제약 전파+probing이 고정하는 변수가 **20×50에서 0/50, 40×100에서 0/100** (40개 인스턴스 전부).
hard 인스턴스는 밀도 0.5·b 중앙값이라 전파 규칙이 한 번도 발동하지 않음. v6~v9에서 MCTS 기여가
0%였던 직접적 원인이 이것 — RL이 축소된 문제가 아니라 원본 크기를 그대로 마주하고 있었음.

**Q2 "몇 개를 고정할지 어떻게 정하나?"** → 학습할 필요 없음. n의 20%를 정확히 고정하면 AHL이
100% 해결하고, **어느 변수를 고르는지도 거의 무관**(무작위 변수 + 정답값도 100%). k는
"오라클 성공률 × 전부맞을확률"이 최대인 지점을 스윕으로 고르면 됨(20×50→k=5, 40×100→k=8).

### 메커니즘은 실재 (오라클), 예측기는 전무

40×100, 동일 예산 40 AHL tries, 24:6 표본:

| 팔 | Solution ACC | 평균시간 | vs a0 |
|---|---|---|---|
| a0_plain (고정 없음) | 62.5% | 9.1s | — |
| a1_lp (LP 신뢰도 고정) | 12.5% | 7.0s | p=0.000 (a0 우세) |
| a2_gnn (기존 GNN 고정, i.i.d.) | 8.3% | 28.3s | p=0.000 (a0 우세) |
| **a4_oracle (정답값 고정)** | **95.8%** | **3.6s** | **p=0.021 (oracle 우세)** |

오라클이 +33.3%p 유의하게 개선하고 **2.5배 빠름** — "8개만 맞으면 40×100은 사실상 풀린다"는
명제는 참. 그러나 사용 가능한 어떤 예측기도 근처에 못 감(변수당 정확도 LP 67~73%, 기존 GNN
68~76%; k=8을 전부 맞출 확률 = 0.73⁸ ≈ 8%, 실측 a2_gnn 8.3%와 정확히 일치).

### 열거 방식 개선은 실제로 효과 있었음 (그러나 확장 안 됨)

i.i.d. 샘플링 대신 **결합확률 상위 T개를 순서대로 열거**(`topT_joint_fixings`)하자 크게 개선:
40×100에서 8.3% → **29.2%**(3.5배), 20×50에서 66.7% → **87.5%**(a0와 통계적 동률, p=1.000).
원인 진단: 기존 GNN이 과신해서 i.i.d. 재시도 10번이 사실상 같은 답 하나였음.

그러나 **예산을 늘리면 격차가 벌어짐** (40×100, k=8, tries=2):

| T (열거 깊이) | a0_plain | a2b_gnn_top | McNemar |
|---|---|---|---|
| 10 | 16.7% | 8.3% | p=0.688 |
| 30 | 62.5% | 29.2% | p=0.039 (a0 우세) |
| 60 | **79.2%** | 25.0% | **p=0.000 (a0 우세)** |

plain AHL은 예산에 비례해 확장되지만(16.7→62.5→79.2%), 고정 방식은 상위 ~30개 패턴을 다 쓰면
정체됨(8.3→29.2→25.0%). **무작위 재시작이 73% 정확도 예측기의 열거보다 같은 예산을 더 잘 쓴다.**

### RL — 구조적 장애로 학습 신호 형성 불가 (완주하지 않음)

`v14_train_fix.py`에 순차적 MDP(k스텝, 매 스텝 축소 인스턴스의 LP 재계산) + REINFORCE를 구현하고
6시간 학습을 시작했으나, 진단 결과 두 가지 문제로 중단:

1. **콜드스타트**: 무작위 초기 정책이 k개를 전부 맞출 확률 = 2⁻ᵏ (k=8에서 0.4%) → 양의 보상을
   한 번도 못 봄. 기존 GNN 증류로 워밍스타트를 구현해 40×100에서 품질 재현(전부정답 17%,
   a2_gnn과 동일)까지는 성공.
2. **탐색이 보상을 파괴함 (본질적)**: 보상이 k개 결정에 대해 전부-아니면-전무라, **8개 중
   어디서든 한 번만 탐색해도 보상이 0이 됨.** 워밍스타트 후에도 40×100 성공률이 0.000에서
   움직이지 않음(온도 0.5). 온도를 더 낮추면 탐색이 사라져 학습 자체가 성립 안 함.
   **신용 할당이 원천적으로 불가능한 보상 구조** — 튜닝으로 해결되는 문제가 아님.

즉 RL은 "돌려봤더니 성능이 안 올랐다"가 아니라 **학습 신호가 형성될 수 없는 구조임을 사전
진단하고 중단**한 케이스. 6시간 학습 완주는 하지 않았음.

### 방법론 노트: 실행 간 분산

a0_plain이 시드만 바꿔도 **20×50 87.5%↔91.7%, 40×100 50.0%↔62.5%(12.5%p)** 로 흔들림.
n=24 표본에서 10%p 내외 차이는 노이즈로 봐야 하며, 향후 결론을 낼 때는 다중 시드 필수.

### 인사이트
1. **차원 축소는 이 문제의 진짜 레버가 맞다** (오라클 +33.3%p, 2.5배 가속, p=0.021).
   문제는 레버를 당길 방법이 없다는 것 — 필요한 변수당 정확도가 90~95%인데 가진 건 73%.
2. **AHL의 무작위 재시작은 생각보다 강한 베이스라인.** 예산을 주면 선형에 가깝게 확장되는 반면,
   부정확한 예측기 기반 열거는 금방 정체된다. "학습된 안내"가 "무작위 반복"을 이기려면
   예측 품질이 임계값을 넘어야 하는데, 이 문제에서는 그 임계값이 매우 높다.
3. **전부-아니면-전무 보상은 RL에 적대적이다.** 부분 점수가 있다고 판단해 시작했으나(v13 대비
   개선점으로 제시), 실제로는 k개 결정이 AND로 묶여 있어 부분 점수가 존재하지 않았음.
   이건 v14 설계 단계에서 놓친 부분이고, 실측으로 드러났음.

- **best.pth 갱신 없음**

## v15 (2026-09-07): 베이즈 한계 측정 — **11사이클 만의 첫 긍정 결과**

**동기**: 학습 실패 11번을 "신호가 없다"로 결론짓기 전에, **정말 없는지를 측정**한 적이 없었음.
생성기가 x*를 심고 b=Ax*를 공개하므로 사후분포는 해집합 S 위에 균등하고,
진짜 주변확률 p_j = P(x_j=1|A,b) = |{x∈S: x_j=1}|/|S| 은 S를 전수열거하면 **정확히 계산 가능**.

### 1) 베이즈 상한 측정 (`v15_bayes_limit.py`)

10×25 인스턴스의 해집합을 CP-SAT로 전수열거(중앙값 |S|=24~29, 인스턴스당 1초 미만):

- **베이즈 변수당 정확도 상한 = 69.9%** (held-out 400개 기준), top-3 확신변수 기준 **93.1%**
- 즉 **신호는 존재한다** — 무작위(50%)보다 확실히 높음. 다만 상한 자체가 낮음.
- 이전 사이클들의 "다중해라 사후확률이 평평해서 학습 불가"라는 설명은 **과장이었음**.

### 2) 원인 가설: 지금까지 **노이즈를 학습**시켜 왔다

|S|의 중앙값이 24~29인데 모든 학습이 심어진 x* **하나**를 하드 라벨로 사용해왔음
(`LPneuroBLS_v7.py`의 expert imitation: `tgt_act = int(x_gt[tgt_var])`).
x*는 정답이 아니라 S에서 뽑힌 표본 하나이고, 베이즈 예측조차 x*와 66~70%만 일치 →
**실질적으로 30% 라벨 노이즈로 학습**해온 셈. 게다가 각 인스턴스를 사실상 한 번씩만 보므로
노이즈가 평균화될 기회도 없었음.

### 3) 통제 실험 (`v15_make_marginal_labels.py`, `v15_train_marginal.py`)

train pool에서 4,004개 인스턴스에 정확한 주변확률 라벨 생성(18초). 아키텍처·데이터·옵티마이저
동일, **학습 타겟만** 하드(x*) vs 소프트(p_j)로 바꿔 학습. 평가는 별도 test pool 400개(전수열거 완료분):

| 모델 | 전체 정확도 | top-3 | top-5 | 주변확률 L1 |
|---|---|---|---|---|
| **베이즈 상한 (이론)** | **69.9%** | **93.1%** | **90.5%** | 0.0000 |
| v15 hard 라벨 학습 | 68.6% | 87.4% | 85.2% | 0.1261 |
| v15 soft 라벨 학습 | 67.7% | 87.2% | 85.3% | **0.0977** |
| 기존 GNN (best.pth) | 60.7% | 72.0% | 69.5% | 0.1813 |
| LP 완화 | 60.6% | 64.5% | 64.1% | 0.3213 |

### 4) 결과 해석 — 가설은 **부분적으로만** 맞았음

**맞은 부분**: soft 라벨이 주변확률 추정을 확실히 개선(L1 0.1261 → 0.0977, −22%).
노이즈 라벨이 실제로 추정 품질을 해치고 있었다는 증거.

**틀린 부분**: **하드/소프트 라벨 간 분류 정확도 차이는 사실상 없음**(68.6% vs 67.7%,
top-3 87.4% vs 87.2%). 라벨 노이즈가 "학습 실패의 주원인"이라는 가설은 **기각**.

**예상 못한 진짜 발견**: 두 신규 모델 모두 **기존 GNN을 크게 앞지름**
(60.7% → 68%대, top-3 **72.0% → 87%대, +15%p**). 그리고 상한(69.9%/93.1%)에 **매우 근접**.
즉 문제는 라벨이 아니라 **기존 모델이 이 과제에 최적화되지 않았던 것** —
best.pth는 MCTS용 다중헤드(select/assign/value/feasibility) 모델이고,
v15의 MarginalNet은 주변확률 예측 단일 목적의 작은 전용 모델(hidden=64, 4층).

**LP 완화의 위치도 명확해짐**: L1 0.3213으로 주변확률 추정치로는 매우 나쁘지만,
argmax 분류 정확도는 60.6%로 기존 GNN(60.7%)과 동일 — v15 이전까지 GNN이
"LP를 복사하는 수준"이었다는 v15 초기 관찰과 일치.

### 5) 인사이트
1. **이 문제에 학습 가능한 신호는 존재한다** (상한 69.9%, top-3 93.1%). 11번의 부정 결과는
   "신호 부재"가 아니라 상당 부분 **잘못된 모델·잘못된 과제 설정** 탓이었을 가능성이 큼.
2. **작고 전용화된 모델이 크고 다목적인 모델을 이긴다.** 파라미터가 훨씬 적은 MarginalNet이
   best.pth를 top-3 기준 15%p 앞섬. 다목적 헤드가 표현을 희석시켰을 가능성.
3. **다만 상한이 낮다는 사실은 그대로.** top-5를 85%로 맞춰도 5개 전부 맞을 확률은
   0.85⁵≈44%. v14의 고정 전략에 적용하면 현재 29%보다는 낫지만 극적이진 않을 것.
4. **미검증**: 이 개선이 20×50/40×100으로 전이되는지, 그리고 실제 해 찾기 성능으로
   이어지는지는 아직 측정 안 됨(10×25는 전수열거가 가능해서 선택된 크기).

### 6) 상한 추적 실험 — |S|를 통제해 상한을 실험 변수로 (`v15_gen_by_m.py`, `v15_ceiling_sweep.py`)

n=25를 고정하고 m을 올리면 |S|가 줄어 상한이 올라감. 각 m에서 **동일 모델·동일 설정**으로 학습:

| m | \|S\| 중앙값 | 유일해 | 베이즈 상한 | v15 모델 | **상한과의 격차** | 기존 GNN | LP |
|---|---|---|---|---|---|---|---|
| 10 (hard 계열) | 24 | 0% | 70.5% | 68.5% | **1.9%p** | 60.9% | 61.2% |
| 14 | 1 | 76% | 96.0% | 76.5% | **19.6%p** | 71.9% | 71.9% |
| 16 | 1 | 97% | 99.2% | 81.2% | **17.9%p** | 78.5% | 78.4% |
| 20 | 1 | 100% | 100.0% | 99.5% | 0.5%p | 97.0% | 99.5% |

**세 개의 구간이 뚜렷하게 갈림**:

1. **m=10 (우리 hard 계열)**: 모델이 상한의 1.9%p 이내로 **포화**. 즉 **가용 정보를 거의 다 뽑아냈고,
   병목은 모델이 아니라 상한 자체(70.5%)**. 그리고 그 상한이 낮은 건 우리가 유일성을 폐기하고
   vertex_spread를 최대화해서 |S|를 키웠기 때문 — **자초한 정보이론적 한계**.
2. **m=14~16**: 상한은 96~99%로 높은데 모델은 76~81%에 그쳐 **18~20%p 격차**. 정보는 존재하는데
   못 뽑는 구간 = **계산적 벽**. 상한이 높다는 건 해가 유일하다는 뜻이고, 그 정보를 뽑는 것은
   곧 인스턴스를 푸는 것(NP-hard). 여기서 NP-hardness가 격차로 드러남.
3. **m=20**: LP 완화만으로 99.5% — 문제가 자명해짐. 학습의 여지 자체가 없음.

**즉 학습이 큰 실용적 이득을 주는 구간이 존재하지 않음**: 상한이 낮은 곳(m=10)에서는 이미
도달했지만 상한이 쓸모없고, 상한이 높은 곳(m=14~16)에서는 도달하는 것이 곧 NP-hard 문제를
푸는 것이며, 더 높은 곳(m=20)은 LP가 이미 해결.

**LP와의 관계**: 모델의 LP 대비 우위가 m이 커질수록 축소됨(+7.3 → +4.6 → +2.8 → 0.0 %p).
기존 GNN(best.pth)은 전 구간에서 LP와 사실상 동일(60.9 vs 61.2, 71.9 vs 71.9, 78.5 vs 78.4) —
**LP를 복사하는 수준 이상을 학습하지 못했음**이 4개 구간에서 일관되게 확인됨.

### 7) 최종 인사이트 (v15 종합)
1. **학습 자체는 작동한다.** 전용 소형 모델이 기존 다중헤드 모델을 크게 앞서고(top-3 72%→87%),
   우리 hard 계열에서는 이론적 상한의 1.9%p 이내까지 도달. 11번의 부정 결과 중 상당수는
   "학습 불가"가 아니라 **모델·과제 설정 문제**였음.
2. **그러나 그것이 문제를 풀어주지는 않는다.** 우리 인스턴스 계열의 상한이 70.5%로 낮고,
   상한이 높은 계열에서는 상한 도달 자체가 NP-hard. **학습이 이길 수 있는 구간이 구조적으로 없음.**
3. **"신호가 없다"는 이전 설명은 부정확했다.** 정확한 표현은 **"신호는 있으나 총량이 작고
   (다중해 때문), 총량이 큰 곳에서는 추출이 NP-hard"**.

## v16 (2026-09-09): 탐색 깊이별 정보량 — **학습이 들어갈 창(window)이 실재함**

**동기**: v15의 70.5% 상한은 **루트에서 한 번 보고** 예측하는 경우의 값. 탐색은 트리를 내려가며
연역으로 정보를 만들어내므로, 조건부 상한 `P(x_j=1 | A, b, 부분배정)`은 더 높음. 다만 상한이
올라가더라도 **그 지점을 전파(propagation)가 이미 해결해버리면 학습은 불필요**하므로,
진짜 질문은 "신호는 높은데 연역은 아직 못 푸는 깊이 구간이 있는가".

### 측정 (`v16_depth_information.py`, n=25 hard, 150 인스턴스, LP 확신 순서)

실제 해의 접두사로 조건화(= 탐색이 옳은 경로를 따라간다는 낙관적 가정):

| 깊이 | 살아남은 \|S\| | 조건부 상한 | 전파가 강제하는 비율 | 학습 창 |
|---|---|---|---|---|
| 0 | 25.2 | 70.5% | 0.0% | 0.205 |
| 2 | 9.2 | 75.6% | 0.0% | 0.256 |
| 4 | 4.1 | 81.7% | 0.4% | 0.315 |
| 6 | 2.2 | 88.8% | 2.6% | 0.378 |
| **8** | 1.6 | **93.4%** | **8.2%** | **0.398 ← 최대** |
| 10 | 1.3 | 96.8% | 22.8% | 0.361 |
| 12 | 1.1 | 98.6% | 56.7% | 0.210 |
| 15 | 1.0 | 99.7% | 94.6% | 0.027 |
| 18 | 1.0 | 99.6% | 97.8% | 0.011 |

(학습 창 = (상한−0.5) × (전파가 강제하지 **못한** 비율))

### 결과 — 창은 실재하고 깊이 6~10에 있음

- 조건부 상한이 루트 70.5% → 깊이 8에서 **93.4%**로 크게 상승
- 그 지점에서 전파는 **8.2%만** 강제 — 연역이 아직 대부분을 못 풀고 있음
- 학습 창이 깊이 8에서 최대(0.398)로, **루트(0.205)의 약 2배**
- 깊이 15 이후에는 전파가 94~98%를 강제해 학습의 여지가 사라짐

### 이전 MCTS 실패(v5~v9 기여 0%)의 재해석

창이 없어서가 아니라, **그 창을 쓸 모델이 없었기 때문**일 가능성이 큼. v15에서 확인했듯
기존 best.pth는 전 구간에서 LP와 동일한 수준(60.9 vs 61.2 등)이었으므로, 깊이 8에서 93.4%의
정보가 있어도 LP 수준의 예측밖에 못 냈을 것.

### 단, 낙관은 금물 — 두 가지 제약

1. **깊이 8 노드는 |S|≈1.6, 즉 거의 유일해 상태**인데, v15의 m-스윕에서 바로 이 구간
   (m=14~16, 유일해, 상한 96~99%)에서 모델이 **18~20%p 미달**했음. 따라서 실제로는
   93.4% 중 75~80% 정도만 잡을 가능성이 큼.
2. **창에 진입하는 것 자체가 문제.** 깊이 8에 도달하려면 8개를 먼저 맞혀야 하는데,
   루트 정확도 70.5%면 0.705⁸ ≈ 6%. 백트래킹으로 보완해야 하며, 이 진입 비용이
   창의 이득을 상쇄할 수 있음.

루트가 아니라 **깊이 d 상태에서 조건부 예측**을 학습한 v15급 모델을 만들어 트리 탐색에 넣고,

- **FREE는 문제가 아님**: 모델이 52~60%로 이론 하한(50%) 근처 — 정상이며 개선 대상이 아님.
- **가장 놀라운 수치: 단위 전파가 FORCED의 0.9~7.5%만 탐지.** 논리적으로 결정된 변수의
  92~99%가 전파에 보이지 않음. 반면 LP 정수값은 66~77%를 잡음 — LP가 강한 경쟁자였던 이유.

### 2) probing 실험 (`v18_probing_recall.py`)

"반대값을 넣어보고 모순이면 강제된 것"이라는 고전 기법의 회수율 측정:

| 깊이 | FORCED 비율 | prop-probe | **LP-probe** | LP 정수값 | **union(LP-probe ∪ 정수값)** | 비용 |
|---|---|---|---|---|---|---|
| 5 | 58.8% | 3.4% | 62.2% | 64.3% | **82.8%** | 2.32 ms/변수 |
| 6 | 71.5% | 6.8% | 68.1% | 71.8% | **87.0%** | 2.17 ms/변수 |
| 7 | 83.6% | 13.4% | 75.0% | 70.7% | **87.8%** | 2.18 ms/변수 |
| 8 | 90.1% | 16.4% | 79.4% | 74.8% | **92.0%** | 2.16 ms/변수 |

### 결론 — 남은 정보는 **학습 대상이 아니라 고전 기법 대상**

- 순수 고전 조합(LP-probe ∪ LP 정수값)이 FORCED 변수의 **82.8~92.0%를 회수**.
  학습 모델의 FORCED 정확도(87.9~90.4%)와 **동급이거나 그 이상**이며, 학습이 전혀 필요 없음.
- 기존 파이프라인의 `apply_probing()`이 3.4~16.4%밖에 못 잡는 건 **1-ply 전파 기반이라 약해서**.
  같은 아이디어를 LP로 하면 62~79%로 뛴다.
- 비용은 변수당 ~2.2ms. 깊이 7에서 자유 변수 18개면 노드당 ~40ms로, AHL 1회 시도(10~300ms)와
  비슷하거나 저렴.

### 인사이트 (v15~v18 종합)
1. **깊이 6~7의 "아무도 못 잡는 정보"는 실은 고전 probing이 잡을 수 있는 정보였다.**
   v16이 창을 찾고, v17이 학습으로 절반만 메우고, v18이 그 나머지가 probing 영역임을 확인.
2. **이 문제에서 학습이 기여할 수 있는 순수 영역은 계속 축소됐다**:
   루트 예측(v15, 상한 70.5%) → 트리 내부(v17, LP가 대부분 잠식) → 깊이 6~7(v18, probing이 잠식).
3. **개선 방향은 명확하고 학습과 무관**: 파이프라인의 probing을 전파 기반에서 **LP 기반으로 교체**.
   이는 구현이 단순하고 비용도 감당 가능하며, 효과는 위 표로 이미 정량화됨.

## v19 (2026-09-09): 비용 축을 넣자 학습의 자리가 생김 — **v18 결론 정정**

**동기**: v15~v18은 전부 **정확도**만 비교했고 **비용**을 한 번도 재지 않았음. 그런데 LP-probe는
**변수당** LP를 한 번씩 풀고, 네트워크는 **한 번의 forward로 전 변수**를 답함. 수천 노드를 도는
탐색에서 비용은 각주가 아니라 사용 가능 여부를 가르는 축임.

### 측정 (`v19_cost_benefit.py`, 단일 스레드, 동일 상태, 노드당 전 변수 판정)

| 깊이 | 변수 수 | **모델 ms** | 모델 정확도<br>(FORCED) | **LP-probe ms** | LP-probe 탐지율<br>(FORCED) | **속도차** |
|---|---|---|---|---|---|---|
| 5 | 20.0 | **1.59** | 89.9% | 36.85 | 60.5% | **23.1x** |
| 6 | 19.0 | **1.61** | 91.3% | 35.30 | 68.8% | **22.0x** |
| 7 | 18.0 | **1.58** | 88.2% | 32.74 | 77.9% | **20.8x** |
| 8 | 17.0 | **1.59** | 88.5% | 30.99 | 79.8% | **19.5x** |

### v18 결론 정정
v18에서 "고전 조합(82.8~92.0%)이 모델(87.9~90.4%)과 동급 이상이므로 학습 불필요"라고 썼는데,
**서로 다른 양을 비교한 오류**였음:
- **probing 수치 = 탐지 재현율.** 발화하면 그건 **증명**(100% 확실). 나머지는 기권.
- **모델 수치 = 추측의 정확도.** 전 변수에 답하지만 보장은 없음.

정정된 비교: **보장이 필요 없는 용도(탐색 안내)에서는 모델이 20배 빠르면서 적중률도 높음.**
보장이 필요한 용도(변수를 영구 확정하는 건전한 전파)에서는 probing이 필수이고 모델로 대체 불가.

### 학습의 정당한 역할: 비싼 추론의 **상각(amortization)**
이는 조합최적화에서 학습이 성공한 표준 형태와 동일한 구조 — learn2branch가 strong branching
(정확하지만 매 노드에 쓰기엔 너무 느림)을 네트워크로 모방해 대부분의 이득을 훨씬 싼 비용에
얻는 것과 같음. 우리 데이터가 지지하는 주장은:
- ❌ "학습이 고전 기법이 못 찾는 정보를 찾는다" (v15~v18이 반증)
- ✅ **"학습이 고전 추론을 20배 싸게 만들어 탐색 안에서 실제로 쓸 수 있게 한다"**

### 남은 검증 (미실시)
동일 wall-clock 예산에서 **모델 안내 탐색 vs LP-probe 안내 탐색**을 비교해야 속도 우위가
실제 탐색 성능으로 이어지는지 확정됨. 지금까지는 노드 단위 비용·정확도만 측정.

## v21 (2026-09-10, 진행 중): 크기 전이 — 20×50까지 학습해 40×100 공략

**가설**: v20에서 10×25 학습 모델이 20×50(2배)에서는 통했고 40×100(4배)에서는 무효였음.
한 단계 위로는 전이되므로, **20×50까지 학습하면 40×100(2배)으로 전이될 수 있다**.

**실행 가능성 확인 (선행 측정)**: 20×50 hard 인스턴스의 |S| 중앙값이 **2개**(10×25의 24개보다
작음 — 제약이 20개로 늘어 해공간이 더 좁혀짐). 전수열거가 인스턴스당 **0.5초**로 가능해
근사 없이 정확한 조건부 라벨 생성 가능. 큰 크기에서 라벨을 못 만든다는 v20의 우려는 해소됨.

**계획**:
1. 20×50 해집합 전수열거 → 조건부 라벨
2. **10×25 + 20×50 혼합** 학습(크기 다양성이 전이에 유리, 파이프라인의 기존 관례와 일치)
3. 내재적: 20×50 깊이별 정확도 vs 조건부 상한
4. **외재적(핵심): 40×100 탐색 비교** — v20의 lp/lp_probe/구모델 결과와 동일 조건 대조
5. 20×50 회귀 확인(구모델 대비 나빠지지 않는지)

**사전 등록한 판정 기준**: 40×100에서 신규 모델이 lp arm을 **인스턴스 단위로** 유의하게
앞서야 성공(v20에서 구모델은 model만 2개 / lp만 2개로 완전 상쇄되어 우열 없음).

전체 78.6% vs LP 75.0%(+3.6%p) vs v15 루트전용 72.0%(+6.6%p). 얕은 깊이에서 특히 강함
(깊이 0: 69.9% vs LP 61.8%, +8.1%p). **단 상한과의 격차가 20.1%p**로, v15 m-스윕이 예고한

### ⚠️ 위 "전이 실패" 판정은 **오독이었음 (2026-09-10 사후 정정)**

탐색 결과만 보고 "크기 전이 실패"로 결론냈으나, 예측 정확도를 직접 재보니 **모델은 40×100으로
정상 전이됨**:

| 크기 | v17 (10×25만 학습) | v21 (혼합) | LP |
|---|---|---|---|
| 10×25 | 67.8% | 64.8% | 56.8% |
| 20×50 | 69.5% | 69.0% | 62.3% |
| **40×100** | **69.4%** | **69.6%** | 64.7% |

40×100에서도 정확도가 유지되고 LP 대비 우위(+4.7~4.9%p)도 그대로임.

**진짜 원인: 순수 DFS가 40×100을 감당하지 못함.** n=100이면 트리가 2^100이라 변수당 5%p 나은
안내로 메울 수 있는 격차가 아님. 결정적 근거로 **실제 v9 파이프라인은 같은 40×100을 54~62%
해결함**(AHL 사용). v20이 안내 품질을 격리하려고 AHL을 의도적으로 제외한 결과, 40×100을
아무도 못 푸는 조건으로 만들어놓고 그것을 "전이 실패"로 잘못 읽은 것.

**교훈**: 어떤 컴포넌트를 격리하려고 다른 컴포넌트를 제거할 때, 그 제거가 특정 크기에서
과제 자체를 불가능하게 만들 수 있음. 격리 실험의 결론은 격리된 조건 안에서만 유효함.

**부수 측정 (m/n=0.4 고정 시 |S|)**: 10×25 → 27, 20×50 → 2, 40×100 → 전수열거 불가(30초 내
CP-SAT가 해를 다 못 찾음). 크기가 커질수록 같은 비율에서도 해가 급격히 줄어듦.

### 인사이트 (정정 반영)

### ceiling 해석의 범위 (2026-09-11 논문에 반영)

측정한 Bayes ceiling은 **심어진 x*를 변수별로 식별하는 것**의 상한이지, solver가 실제로 하는 일
(**𝒮의 아무 원소나 찾기**)의 상한이 아니다. 둘은 갈라진다 — 제약이 없는 instance는 |𝒮|=2^n이므로
ceiling이 정확히 50%(최악)인데 푸는 것은 자명하다. **낮은 ceiling ≠ 어려운 문제**.

실측으로도 두 축은 무관하다: 21×60에서 풀린 27개에 대해 |𝒮|(2~40)와 탐색 시간의
**Spearman ρ=−0.04 (t=−0.18, 유의하지 않음)**. 측정 가능한 범위에서 solution multiplicity는
탐색 난이도를 어느 방향으로도 예측하지 않는다.
(주의: Pearson on logs는 −0.154로 약한 음의 관계처럼 보이나 rank 상관은 0에 가깝다. 전자로
"해가 많으면 쉽다"고 주장해서는 안 된다.)

**그럼에도 측정이 의미 있는 이유 2가지**:
1. 이전 사이클 전부가 x*를 변수별 label로 학습했으므로, ceiling은 **그 학습 설정들이 마주했던
   상한** 그 자체다. 기존 network 60.7% vs ceiling 69.9% vs LP 60.6%은 문제가 아니라 **설정을 진단**한다.
2. ceiling이 유도하는 **FORCED/FREE 분해**가 탐색에서 운용상 의미를 갖는다:
   - **FREE**(0<p_j<1): 양쪽 자식 모두 해를 포함 → **어느 쪽으로 분기해도 틀리지 않음**
   - **FORCED**(p_j∈{0,1}): 거슬러 분기하면 subtree가 비어 **backtrack 확정**
   즉 marginal은 "x*와 일치할 확률"이 아니라 **"이 배정으로 𝒮의 몇 %가 살아남는가"**로 읽어야 하고,
   비용을 발생시키는 것은 FORCED 오류뿐이다. v18이 잔차를 총계가 아니라 FORCED/FREE로 분해한 이유이며,
   모델이 FREE에서 50% 근처인 것이 실패가 아니라 정상인 이유다.

### root ceiling 서술의 전면 재배치 (2026-09-11)

사용자 지적으로 논문 전체를 전수조사해 **root ceiling 69.9%를 헤드라인에서 내리고
FORCED/FREE 분해를 논문의 척추로 올렸다.** 근거가 된 신규 측정:

| root 변수 (10×25, 24개 인스턴스) | 개수 | 비중 | 해당 부분집합 ceiling |
|---|---|---|---|
| **FORCED** (거슬러 분기 → subtree 빔) | 38 | **6.3%** | **100.0%** |
| **FREE** (어느 쪽이든 해에 도달) | 562 | **93.7%** | 67.2% |
| 전체 (= "69.9% 헤드라인") | 600 | 100% | 69.3% |

즉 **69.9%라는 수치의 94%가 backtrack을 유발할 수 없는 변수에서 나온다.** root ceiling은
"이 문제가 얼마나 어려운가"가 아니라 "심어진 해를 얼마나 식별하기 어려운가"이며, 정작 중요한
6.3%에서는 ceiling이 이미 100%다(= 정보는 다 있고, 질문은 무엇이 그걸 탐지하느냐).

**깊이에 따른 역전**: FORCED 비중이 root 6.3% → depth 8 **89.0%**. 즉 쓸모 있는 정보가
없는 게 아니라 **아무도 보지 않던 깊이에 있었다**. 이것이 논문의 새 서사다.

수정 지점: 초록, §1.3 기여 (1)(2), §4.2(제목 + 표 2b 신설 + 해석부), §4.4(역전 명시),
결론, 한계. 영문 31→32쪽, 한글 15→17쪽.

## v23 (2026-09-14): 리뷰어 관점 자체점검 — 결함 3건과 누락 baseline 1건

사용자 요청으로 "엄밀한 리뷰어라면 무엇을 지적할까"를 자체 점검하고, 지적 사항을 실측으로 검증함.
**셋 다 결과를 우리에게 유리한 방향으로 왜곡하던 것들이라, 외부 리뷰 전에 잡은 것이 다행.**

### 결함 1: 비용 비교가 apples-to-oranges (표 6)
`v19_cost_benefit.py`가 `featurize()`(노드 LP relaxation 풀이 포함)를 **타이머 밖**에서 호출하고
forward pass만 계측. network는 그 LP 없이 동작 불가인데 LP-probing은 모든 LP가 계측에 포함됨.

| depth | 논문 주장 | **정정** |
|---|---|---|
| 5 | 23.1x | **9.6x** |
| 6 | 22.0x | **9.7x** |
| 7 | 20.8x | **9.1x** |
| 8 | 19.5x | **8.2x** |

→ "19~23배"는 실제 **8~10배**. 약 2.4배 과장이었음. 코드 수정 완료(주석 포함).
**탐색 실험(표 7)은 두 arm 모두 LP를 지불하므로 영향 없음** — 독립 비용표만 틀렸다.

### 결함 2: seed가 재현 불가능
`seed = abs(hash(inst_path.name)) % 2**31` — Python은 PYTHONHASHSEED로 문자열 해싱을
프로세스마다 무작위화한다. 검증: 같은 문자열로 3개 프로세스 → 1834577131 / 1023114754 / 381048208.
**즉 지금까지 모든 실행이 서로 다른 미기록 seed로 돌아갔고, 보고된 어떤 수치도 재현 가능한
출처가 없었다.** `zlib.crc32` + `--seed_offset`으로 교체.

### 결함 3: 누락된 baseline — classical solver (가장 치명적)
논문이 §2.2에서 CP-SAT를 설명만 하고 실험에서 비교하지 않았음. 동일 평가셋·단일 스레드·동일 예산으로 측정:

| 크기 | **CP-SAT 중앙** | SCIP 중앙 | 제안 방법(model) 중앙 | CP-SAT 대비 |
|---|---|---|---|---|
| 10×25 | **0.002초** | 0.009초 | 0.08초 | **40배 느림** |
| 18×50 | **0.046초** | 0.385초 | 2.84초 | **62배 느림** |
| 21×60 | **1.159초** | 3.687초 | 47.28초 | **41배 느림** |

전부 30/30 해결. **제안 방법이 어느 크기에서도 classical solver를 이기지 못한다.**
우리가 relaxation용으로 이미 쓰고 있는 SCIP조차 13배 빠르다.
→ 기여를 "solver 성능"이 아니라 **"branching guidance의 지도학습 방법론"**으로 재진술해야 함.

### 추가 검증: MLP ablation (graph가 필요한가)
"특징이 6개뿐인데 GNN이 필요한가"라는 예상 지적을 선제 검증:

| 모델 | 정확도 | marginal L1 | 파라미터 |
|---|---|---|---|
| linear (3 feat) | 78.1% | 0.2530 | **4** |
| MLP (3 feat) | 77.8% | 0.2522 | 8,641 |
| MLP + 제약 집계 (9 feat) | 79.4% | 0.2361 | 9,025 |
| **MarginalNet (graph)** | **84.1%** | **0.1514** | 21,761 |
| Bayes ceiling | 87.3% | — | — |

**graph 구조는 실제로 기여한다**(MLP 대비 +4.7%p, L1 36% 개선, 상한까지 남은 격차의 60% 회수).

### warm start 비용 재측정 — amortization 주장의 규모 정정

Gurobi incremental LP(bound만 변경, 부모 basis에서 재최적화)로 양쪽을 다시 재니:

| 조건 | network | probing | 배수 |
|---|---|---|---|
| 논문 원본 (featurize 제외, SCIP 재구성) | 1.6ms | 31~37ms | 19~23× |
| 정정 1 (featurize 포함) | 4.4~5.2ms | 40~50ms | 8~10× |
| **정정 2 (양쪽 warm start, n=17~20)** | **2.4ms** | **4.0ms** | **1.3~1.7×** |

**그러나 크기에 따라 스케일한다** (메커니즘: network는 LP를 O(1)회, probing은 O(n)회):

| n | 25 | 50 | 60 | 100 | 150 |
|---|---|---|---|---|---|
| 배수 | 1.7× | 5.1× | 7.2× | 15.5× | **17.8×** |

다만 **우위가 큰 구간(n≥100)에서는 탐색 자체가 작동하지 않는다**는 한계도 함께 명시.
