# `*_instances_hard_*` 생성 방법론

**생성 스크립트**: `proposed_src/generate_hard_instances.py`
**검증 스크립트**: `proposed_src/validate_hard_instances.py`
**생성일**: 2026-08

## 왜 만들었나

`dnsms` 생성기(`gen_planted_instance`, market-split)로 만든 인스턴스는 CP-SAT/Gurobi/SCIP가 40×100까지 압도적으로 빠르고 정확하게 풀어낸다는 것이 baseline 재검증(2026-07)에서 확인됐다. 이후 CP-SAT의 실제 탐색 노력(branches/conflicts/wall-time)을 좌우하는 요인을 인스턴스 500개×2크기 규모의 회귀분석으로 찾았고, **LP 완화(relaxation)의 실수해 폴리토프가 클수록 CP-SAT가 뚜렷하게 느려진다**는 것이 가장 강하고 독립적인 원인으로 확인됐다(20×50에서 wall-time과의 상관계수 0.825, 하위/상위 10% 그룹 간 약 120배 시간 차이). 본 생성기는 이 원인을 직접 겨냥해 의도적으로 CP-SAT가 풀기 어려운 인스턴스를 만든다.

## 문제 정의 변경사항 (CLAUDE.md도 함께 수정됨)

기존 `legacy` 생성기는 심어놓은 해가 **유일한 이진해**가 되도록 강제 검증했다. 이번 조사에서 이 유일성 강제가 오히려 LP 폴리토프가 작은(=CP-SAT에게 쉬운) 인스턴스만 선택하는 부작용이 있다는 것이 확인되어, 본 생성기는 **유일성을 전혀 검증하지 않는다** — CLAUDE.md의 "단일해 존재" 가정도 이에 맞춰 수정했다(다수 해 허용, 목표는 $\mathcal{S}$의 원소 하나를 찾는 것).

## 생성 알고리즘

### 1. Feasible 인스턴스 — "K개 후보 중 최선 선택"

1. $A \in \{0,1\}^{m\times n}$을 밀도 0.5의 베르누이 랜덤으로 생성 (행당 비영 원소 ≥2, 열당 ≥1 재보장, 위반 시 재생성).
2. 동일한 $A$에 대해 후보 해 $x^{(1)}, \dots, x^{(K)}$를 독립적으로 심는다(각각 $n$개 변수 중 무작위로 정확히 $n/2$개를 1로 설정).
3. 각 후보에 대해 $b^{(k)} = Ax^{(k)}$를 계산하고, **vertex_spread**(무작위 방향 4개로 LP를 풀어 얻은 서로 다른 정점들의 평균 쌍별 L2 거리)를 계산한다.
4. vertex_spread가 가장 큰 후보 $(A, b^{(k^*)}, x^{(k^*)})$를 채택한다.

**$K=20$**을 사용했다 — 비용(후보당 LP 4회 풀이) 대비 얻는 난이도 상승이 이 지점부터 완만해지는 것을 사전 실험으로 확인했다(20×50 기준: K=5→3.35, K=10→3.49, K=25→3.62, K=40→3.66, 단위는 vertex_spread 평균값).

**시도했으나 폐기한 방법**: 처음에는 "$b_i$를 각 행 rowsum의 25~75% 구간에 강제"하는 방식(사용자 최초 요청)을 구현했으나, 검증 결과 **일반 dnsms 인스턴스가 이미 83~100% 확률로 이 구간을 자연스럽게 만족**하고 있어(40×100은 300/300, 100%) 사실상 아무것도 거르지 못하는 방법임이 밝혀졌다. $x$를 정확히 $n/2$개씩 심는 현재 관례 자체가 $b$를 통계적으로 중앙 근처로 몰아주기 때문이다. 이후 vertex_spread를 직접 최대화하는 현재 방식으로 교체했다.

### 2. Infeasible 인스턴스 — "자연적 기반 + 섭동 + CP-SAT 인증"

Feasible 인스턴스와 달리 **$K=1$(선택 없음, 자연적 생성)** 기반을 사용한다.

**이유**: $K=20$으로 만든 극단적으로 "느슨한"(폴리토프가 큰) feasible 인스턴스는 1~5행을 ±1~±3 섭동해도 LP 완화 자체가 거의 깨지지 않는다는 것을 직접 실험으로 확인했다(느슨한 폴리토프는 작은 섭동을 흡수해버림 — 5행 ±3 섭동에도 LP infeasible 발생률 1/8 수준). CP-SAT로 정수 infeasibility를 증명하려 시도하면 개별 인스턴스가 타임아웃(15초)에 반복적으로 걸려 생성 자체가 사실상 진행되지 않았다. Feasible과 infeasible의 "어려움"은 서로 다른 메커니즘(해 공간의 크기 vs 부재를 증명하는 어려움)이라 판단해, infeasible 생성에는 자연적 기반을 사용하기로 했다.

절차:
1. $K=1$ 기반으로 feasible $(A, b_{\text{feas}})$를 생성.
2. $1\sim3$개 행을 무작위 선택해 $\pm1$ 섭동(0~rowsum 범위로 클리핑), $b_{\text{feas}}$와 달라질 때까지 반복.
3. CP-SAT(단일 스레드, 시간제한 15초)로 INFEASIBLE 상태를 확인. 실패(타임아웃 또는 여전히 feasible) 시 다른 섭동으로 재시도(최대 6회), 그래도 실패하면 새 기반으로 재시도(최대 15회).

| 크기 | 중복 | 심은 해 불일치 | feasible:infeasible | infeasible CP-SAT 재확인 | vertex_spread 상승 | 난이도 레벨 분포(1→5) | 평균 레벨 |
|---|---|---|---|---|---|---|---|
| 10×25 | 0/11000 | 0/8800 | 8800:2200 (80/20%) | 200/200, 미해결 0 | **+31.8%** | 0/1/18/52/**129** | 4.54 |
| 20×50 | 0/11000 | 0/8800 | 8800:2200 (80/20%) | 200/200, 미해결 0 | **+40.1%** | 0/0/5/35/**160** | 4.78 |
| 40×100 | 0/11000 | 0/8800 | 8800:2200 (80/20%) | 200/200, 미해결 0 | **+29.4%** | 0/0/4/19/**177** | 4.87 |

- **vertex_spread 상승**: 같은 크기의 자연적(K=1) dnsms 스타일 기준 분포 대비 평균 증가율.
- **난이도 레벨**: `difficulty_index.py`(2026-07 정의, vertex_spread·b_tightness_mean 백분위 평균 기반 5단계) 기준. 세 크기 모두 200개 표본 중 대다수가 최고 난이도(레벨 5)로 분류됨 — 목표대로 CP-SAT에게 어려운 인스턴스가 만들어졌음을 확인.
- **CP-SAT 재확인**: 저장된 infeasible 라벨을 독립적으로 CP-SAT(30초 제한)로 재검증, 200/200 전부 확인됨(미해결 0건) — 라벨 정확성 보장.

## 파일 형식

`{train,test}_instances_hard_{m}x{n}_{count}/` 디렉토리 아래 `<prefix>-{idx:05d}.json`:
```json
{"A": [[0,1,...], ...], "b": [3, 7, ...], "x": [0,1,...] | null, "feasible": true | false}
```
`x`는 feasible 인스턴스에만 존재(심어놓은 해). `feasible=false`인 경우 `x=null`(섭동 후에는 유효한 해가 아니므로).

## 알려진 한계

- Feasible 인스턴스는 vertex_spread 기준으로 "어렵게" 선택됐지만, infeasible 인스턴스는 자연적 기반에서 왔으므로 두 라벨 간 난이도 특성이 대칭이 아니다(위 "왜 K=1을 쓰는가" 참고). Infeasible 쪽의 난이도는 이번 생성 과정에서 직접 최적화되지 않았다 — CP-SAT 15초 시간제한을 통과한 것만 채택했다는 점에서 최소한의 난이도는 보장되지만, feasible 쪽만큼 극단적이지는 않을 수 있다.
- 대규모 재현성 검증(예: baseline 5종 전체를 이 새 데이터셋에 재실행해 실제 CP-SAT 시간이 dnsms 대비 얼마나 늘었는지 직접 측정)은 아직 수행하지 않았다 — 지금까지의 검증은 vertex_spread·난이도지표라는 대리 지표 기준이며, 실제 CP-SAT wall-time 비교는 다음 단계로 남겨둔다.
