================================================================================
v22_transfer/ — |S| 통제 크기 전이 실험 (2026-09-10 ~ 09-11)
================================================================================
동기: v21까지의 전이 실험은 학습/테스트의 |S|가 10배 이상 달라(10x25는 27, 20x50은 2)
"크기 효과인가 |S| 효과인가"를 구분할 수 없었다. n을 고정하고 m을 조절하면 |S|를 통제할 수
있으므로(v15_gen_by_m.py), |S|를 맞춘 크기들로 전이를 재측정한다.
탐색 루프 자체(GUIDES, search)는 util/v20_guided_search.py를 그대로 재사용한다.

[실행 순서 — run_v22_cd.sh 하나로 전 단계가 자동으로 이어진다]

v22_find_m.py               목표 |S|를 주는 m을 찾는 스윕.
                            ** 시간제한에 걸린 열거는 제외하고 센다 ** — 잘린 개수를 중앙값에
                            섞으면 틀린 값이 나온다(실제로 그 버그가 n=100 측정을 오염시켰다).
                            실행: python v22_find_m.py --n 60 --ms 20 21 22 --count 10

v22_sbound_n100.py          전수열거가 불가능한 n=100에서 |S| 하한만 측정한다.
                            고정 시간창 안에 CP-SAT가 찾은 해 개수는 |S|의 유효한 하한이다.
                            결과: m=28~40 전부 20초 내 0개 발견 -> n=100에서는 병목이
                            "안내 품질"이 아니라 "해를 하나라도 찾는 것"이므로 실험 대상에서 제외.

v22_add_solutions.py        주변확률만 저장된 인스턴스 파일에 해집합 S를 다시 붙인다.
                            v15_gen_by_m.py가 p_j만 저장하고 S를 버리는데,
                            v17_make_conditional_data.py는 S가 있어야 깊이 d 상태를 만든다.
                            이 크기에서는 재열거가 싸므로 재생성 대신 backfill한다.

v22_make_testset.py         조건 C/D용 테스트 인스턴스 디렉토리 생성.
                            테스트셋은 주변확률 라벨이 필요 없고 "풀렸는가"만 보면 되지만,
                            |S|는 열거해 저장한다 — |S| 맞춤 주장을 가정이 아니라 검증으로
                            뒷받침하기 위함이다. 열거 미완료 인스턴스는 n_sols=-1로 표시해
                            미검증 |S|가 검증된 것처럼 통과하지 않게 한다.

v22_cascade_search.py       ** 전체 요인설계: arm x {AHL off, AHL on} **
                            v20은 AHL-off 절제만 돌렸는데, 그 조건은 40x100을 모든 arm에게
                            불가능하게 만들어 운용 성능을 말할 수 없었다. 한 크기는 절제로,
                            다른 크기는 운용 조건으로 보고하는 것은 방어 불가능하므로
                            모든 크기/arm에서 두 설정을 다 돌린다.
                              ahl=off  전파 + 안내 분기만. 안내 품질을 격리한다.
                              ahl=on   실제 캐스케이드. AHL을 먼저 돌리고 실패한 것만 탐색.
                                       AHL은 안내 전략과 무관하므로 모든 arm이 정확히 같은
                                       잔여 집합을 받는다 — 선택 편향이 아니라 알고리즘 기술이다.

v22_report.py               여러 번의 호출에 걸친 결과를 하나의 표로 모은다.
                            조건 C와 D는 체크포인트가 달라 별도 실행이므로, 정작 중요한 비교
                            (같은 크기에서 model vs lp, 같은 테스트에서 C의 모델 vs D의 모델)가
                            호출 경계를 넘는다. 안내를 비교할 때는 search_sec(AHL 시간 제외)을
                            쓴다 — AHL은 모든 arm에서 동일하게 돌므로 포함하면 차이가 희석된다.

run_v22_cd.sh               테스트셋 생성 -> 조건 C -> 조건 D -> 리포트를 사람 개입 없이 연결.
                            스크립트 위치를 기준으로 cd하므로 어디서 실행해도 된다.

[결과 요약]
테스트 크기 선정: n=100 탈락(해를 20초 내 0개 발견), n=70 탈락(m=23에서 열거 0/10),
n=60 m=21 채택(|S| 중앙 12, 열거 10/10).
  안내 품질(AHL off): n=60에서 lp 90.0%/190.76s vs model 100%/47.28s.
    속도배수 중앙 2.71배(부호검정 p=0.019), 노드 6.2배 감소.
    lp가 600초를 소진한 3개를 model은 41/230/232초에 해결(McNemar p=0.250, 방향은 3-0으로 일관).
  전이 손실: 같은 n=60 테스트에서 n=25 학습 모델과 n=50 학습 모델이 구별되지 않는다
    (빠른 비율 15/30, 총시간 2924.9s vs 2914.5s, 차이 0.4%). ** 전이 손실 측정되지 않음 **.
  AHL 커버리지: n=25 30/30 -> n=50 24/30 -> n=60 16/30으로 감소.
    n=60의 잔여 14개에서 model은 14/14, lp는 12/14 해결 -> 운용 조건에서도 93.3% -> 100%.

                            LaTeX 원고(docs/tex/SWEVO_KR_v22.tex)를 생성. 컴파일에는 xelatex+xeCJK(또는
